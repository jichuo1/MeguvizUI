# P2 可选能力

这些模块均需显式启用，不改变 core/widgets 的默认依赖。它们提供基础能力；是否适合某个应用，必须由该应用的需求、设备行为与性能测量决定。

| 模块 | Gradle 属性 | 用途与边界 |
| --- | --- | --- |
| [ui-plan](../ui-plan/README.md) | `enablePlan` | 纯数据计划，按验证、解析、绑定、挂载分期；静态页面可继续使用直接 DSL。 |
| [ui-codegen-api / ui-codegen](../ui-codegen/README.md) | `enableCodegen` | KSP 仅根据显式声明生成直接工厂、typed ref 和 registry 注册入口。 |
| [ui-recycler](../ui-recycler/README.md) | `enableRecycler` | 可选 RecyclerView 绑定，最多一个运行中的 diff 与一个最新待办。 |
| [ui-text](../ui-text/README.md) | `enableText` | 默认关闭的长文本预计算；API 27、短文本和带 span 的输入回退普通 setter。 |
| [ui-layouts](../ui-layouts/README.md) | `enableLayouts` | 受限原生横向行；当前采用 LinearLayout，未宣称性能收益。 |
| [ui-prewarm](../ui-prewarm/README.md) | `enablePrewarm` | 可取消的有界主线程预热，复用会话帧驱动，不抢占已开始的工作。 |

启用全部模块并执行主机聚合验证：

```sh
./gradlew -PenableP2=true verifyP2 --no-daemon --max-workers=2
```

`verifyP2` 检查各模块单元测试、lint、发布制品与模块输出的一致性、JVM API 基线和生成器消费应用；仪器 APK 的编译不等于设备测试。独立 Maven 消费应用见 [p2-consumer](../samples/p2-consumer/README.md)。当这些能力被纳入发布范围时，完整候选还要求独立消费者、设备和性能证据。性能、设备或业务准入数据缺失时，不应将这些模块标为已经获得性能收益。

## 性能准入

[p2-benchmark](../samples/p2-benchmark) 对六个模块各做一组同输入 A/B 实验：A 是不用该模块时的写法，B 使用该模块。实验在前台 Activity 中运行，使用不可调试、`speed` AOT 编译的 benchmark 构建，组间按 ABBA 交替，每组 20 次预热、300 个样本，每个样本都会校验产出的原生结构。准入准则写在 [p2_performance_criteria.toml](../build-logic/verification/p2_performance_criteria.toml)，它是测量前定下的设计阈值，也计入源码指纹：

- 非性能目的的模块（plan、codegen、layouts）使用配对比值：同一 ABBA 轮次中的 A、B 样本组成一对，取 B/A 的中位数，按样本对重采样求 bootstrap 95% CI，要求 CI 上界不超过阈值。配对能抵消一对样本共同经历的设备漂移（调频、大小核迁移）。
- 以收益为目的的模块（recycler、text、prewarm）使用两组中位数之比，两组各自独立重采样，要求 CI 上界低于阈值。

```sh
./gradlew -PenableP2=true verifyP2Performance -Pp2PerformanceSerial=<adb serial> -PallowDeviceInstall=true --no-daemon --max-workers=2
```

该任务只安装或替换基准自身的两个包。设备必须是物理机，热状态不得超过 1。结果写入 `build/reports/gates/p2-performance.json`，原始日志写入 `build/reports/device/p2-performance/`。

2026-10-27 按源码指纹 `431d13…` 在 PMA110（Android 17 / API 37，arm64）上的最新实测（每组 300 个样本，热状态前后均为 0/0）如下：

| 模块 | 场景 | 统计 | A 中位 | B 中位 | B/A | 95% CI | 准则 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| plan | 48 节点页面构造 | 配对 | 3.49 ms | 3.71 ms | 1.05 | 1.03–1.07 | 上界 ≤ 1.25 | 准入 |
| codegen | 64 个视图注册挂载 | 配对 | 4.42 ms | 4.48 ms | 1.00 | 0.99–1.02 | 上界 ≤ 1.10 | 准入 |
| recycler | 16 次突发提交、2000 项，到最终列表应用 | 中位数比 | 9.09 ms | 3.37 ms | 0.37 | 0.34–0.41 | 上界 < 0.90 | 准入 |
| text | 3000 字纯文本，主线程应用+测量+布局 | 中位数比 | 1.07 ms | 0.74 ms | 0.69 | 0.68–0.73 | 上界 < 0.90 | 准入 |
| layouts | 8 行构造+测量+布局 | 配对 | 9.39 ms | 9.58 ms | 1.01 | 0.99–1.02 | 上界 ≤ 1.10 | 准入 |
| prewarm | 48 行页面首次切换帧 | 中位数比 | 7.63 ms | 2.45 ms | 0.32 | 0.32–0.33 | 上界 < 0.50 | 准入 |

- recycler 经过两步优化后准入。第一步把稳定 ID 校验和去重从主线程移到后台 diff，并把 ID 存为 `LongArray`，B/A 从 3.47 降到 1.10。第二步新增不可变模型构造器：每次提交只做一次整体数组拷贝，不再逐项快照，B/A 降到 0.37 左右；突发期间主线程提交约 0.14 ms，官方 `ListAdapter` 约为 0.03 ms。带快照函数的原构造器仍按逐项快照计价，只有调用方能保证模型不可变时才适用新构造器。
- plan、codegen、layouts 改用配对统计之前，每组 100 个样本、两组中位数之比，在三轮测量中各有一轮因 CI 过宽而未通过，期间代码没有改动。改用配对统计并增加到 300 个样本后，三项的 CI 宽度都在 ±4% 以内；阈值没有变化。
- text 的收益只针对主线程部分；后台预计算使结果晚约 1.1 ms 才可应用。
- prewarm 把构造挪到切换前的 12 个平台帧中完成，单元耗时中位约 1.1 ms，没有因超出预算被丢弃。
- 不同轮次之间，A 组绝对耗时可能相差两倍以上（设备状态不同），应只比较同一轮内的比值。

这些数字只覆盖一台物理设备、无 R8、分离层级（不含 draw、掉帧和堆）。每个应用仍需以自己的负载重新准入。

## 设备行为矩阵

`verifyP2Matrix`（[p2_matrix.py](../build-logic/verification/p2_matrix.py)）在 [p2-matrix](../samples/p2-matrix) 样例上运行 15 项仪器检查，另外通过 adb 驱动进程死亡恢复，并在设备上运行 R8 混淆后的独立消费者。字号、RTL、语言和深色模式都是应用内配置覆盖，不修改系统设置。

```sh
./gradlew -PenableP2=true verifyP2Matrix -Pp2MatrixSerial=<adb serial> -PallowDeviceInstall=true --no-daemon --max-workers=2
```

2026-10-27 按源码指纹 `431d13…` 运行结果：

| 设备 | 6 模块仪器测试 | 行为矩阵 |
| --- | --- | --- |
| PMA110 真机（OPPO/ColorOS，Android 17 / API 37） | 13/13 | 17/17 |
| 隔离模拟器 API 27 | 13/13 | 17/17 |
| 隔离模拟器 API 29 | 13/13 | 17/17 |

矩阵覆盖：旋转与 `recreate()` 后模型、滚动位置、焦点与稳定 ID 恢复；进程被杀后经任务栈恢复；无障碍节点树（标签、48dp 点击区、标题、列表集合信息、阅读顺序）；Tab/D-pad 遍历与 Enter 激活；2 倍字号无截断；RTL 镜像；RecyclerView 挂窗、开启动画时边滚动边突发提交、payload 被丢弃后完整绑定、diff 后焦点保持；文本在字号、RTL、断行、连字、语言、深色模式组合下预计算结果与普通 setter 的行宽和断行一致；原生行在 4 档字号 × LTR/RTL 下与 LinearLayout 几何、基线、点击区、焦点顺序等价；plan 在字号与 RTL 下与直接 DSL 等价；预热在真实低内存回调、旋转导致的原位资源变化、按 Home 脱离、未就绪时打开和单元超预算时释放暂存页且不残留引用；R8 后的独立消费者能显示生成工厂、plan 和列表内容。

已知缺陷与边界：

- **ui-text（已修复）：** RTL 环境下，如果后台预计算在 TextView 挂载并解析出布局方向之前就完成，提交时和应用时的 `PrecomputedText.Params` 方向不同，结果会被当作过期丢弃，而且之后没有任何路径重新提交，长文本就一直为空。修复前这个问题在 API 37 与 29 上都复现过。现在参数不一致时会用当前参数重新计算最新文本，最多重试两次；重试用尽，或者参数在帧到来前又变化时，改用普通 setter 写入同一文本。`TextInstrumentation` 新增了参数变化重算、重试有界、提交后才解析方向三项用例。
- 旋转与重建用例比较的是旧实例在保存那一刻的实际列表锚点（位置与像素偏移），而不是预设的第 40 行。此前 API 27 上有一次“恢复到第 36 行”的失败，经 30 次旋转加 15 次重建的重复调查查明：那次运行中，初始焦点落在了 RecyclerView 上，准备步骤里的 Tab 把焦点移进了列表，列表跟随焦点滚动，实际保存的锚点已经变成 34/−53，恢复结果与之完全一致，属于测试前提错误，恢复本身没有问题。重复调查中还发现，上一次运行可能把屏幕留在横屏，再请求横屏就不会触发重建；现在用例改为请求与当前方向相反的方向。修正后 API 27 上旋转 30/30、重建 15/15 通过，原始记录在 `build/reports/device/p2-rotation-investigation*/`。
- 在 ColorOS 上，刚切到后台的进程有时不会被 `am kill` 立即杀死；驱动会重试，必要时用应用自身 uid 发送 SIGKILL，并在证据里记录实际使用的方式。
- API 27/29 在隔离模拟器上运行，只能代表平台行为，不能代表 OEM 兼容性；目标 OEM 列表尚未声明。
- 在真机冷启动时，第一个预热单元可能超过默认 2 ms 预算并被丢弃，此时页面在打开时才懒建。这是有意的设计行为，矩阵中按这条路径验收。

## 人工无障碍清单

`verifyP2Matrix` 已自动核对 TalkBack 所消费的无障碍节点树：标签、48dp 点击区、标题、列表集合信息、阅读顺序、Tab/D-pad 遍历与 Enter 激活。下列项需要有人开启 TalkBack 在真机上实听，自动化结果不能代替；每项记录设备、系统版本、TalkBack 版本、操作、期望、实际朗读内容与截图，未执行的保持 blocked。

| 界面 | 操作 | 期望 |
| --- | --- | --- |
| 标题与 plan 行 | 从顶部逐项右滑 | 先读标题并报“标题”，随后依次读 plan 两行，与直接 DSL 页面顺序一致 |
| 生成标签、长文本 | 右滑到长文本 | 完整朗读混合中英文与阿拉伯文段落，不截断、不重复 |
| 原生行 | 右滑经过两行 | 每行先读标签再读按钮，按钮报“按钮”；RTL 下顺序随镜像保持“标签→按钮” |
| 打开页面 | 双击 Open page | 读出新页面首行；预热已就绪与懒建两种路径朗读一致 |
| 列表 | 进入列表、双击 Toggle | 进入时报总行数；切换后读出 On/Off 新状态，焦点留在同一行，不跳回列表顶部 |
| 旋转与重建 | 焦点停在 Pair 时旋转屏幕 | 旋转后 TalkBack 焦点仍在 Pair 或重新落在可预期的位置，不落到窗口外 |
| 字号放大 | 系统字号调到最大后重复以上 | 无截断，点击区可达，朗读内容不变 |

KSP 处理器仅存在于编译期；RecyclerView 依赖仅属于 `ui-recycler`。预计算不会在首次测量时等待 Future；预热不会将普通 View 构造移到后台，也不会自动预建所有页面。
